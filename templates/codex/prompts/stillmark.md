# Stillmark (Codex)

Run `stillmark` from the project root with `--json` for all planning operations. ROADMAP.md is public; `.stillmark/plans/TASK_PLAN.md` is private and local. Classify ambiguous adds with `stillmark classify`. TASK_PLAN.md ends with a generated `## Checklist` (grouped by phase when tasks have `--phase`); never edit it by hand: run `stillmark plan status <task> in-progress` when starting and `stillmark plan done <task>` right after finishing each task. Record finished work with `stillmark roadmap done "<item>"` or `stillmark roadmap add "<description>" --done`; add `--commit=<sha>` when backfilling so the `done:` date comes from git (dates are on by default; `config set --roadmap-dates=false` turns them off). Do not run git yourself; use Stillmark config for optional roadmap commits. When the user asks for a commit, run `stillmark git hook install --json` first so agent attribution trailers are stripped (default on; `stillmark config set --strip-attribution=false` turns it off). Never add agent markers such as `(t)` to the message, and push right after the commit (`git.autoPush`, default on; `stillmark config set --auto-push=false` turns it off, or skip when the user says not to push). `stillmark git push --json` pushes local commits and never commits; when `uncommitted` is not empty, ask whether to commit them first, then run it again.

**User's language (mandatory):** Stillmark is in English, but every message to the user (progress updates, questions, final report) is in the language the user writes in. Translate CLI summaries; keep commands, file names, IDs, and JSON fields as they are.

**Document language (mandatory):** `stillmark config status --json` returns `language.needsPrompt` and `language.resolved` per target (`roadmap`, `plan`, `coverage`, `changelog`, `docs`, `commits`). When `needsPrompt` is true, ask once before writing any file and record it with `stillmark config set --language=<tag> --json`. Write every item, task, coverage case, document, and commit message in that language; headings, IDs, and fields the CLI parses stay as written. Per document: `--module=<target>`; `--language=inherit` removes an override.

**Caveman replies (optional, off by default):** `stillmark config status --json` returns `caveman.rules`; when not empty, follow them in every reply (terse, still in the user's language, commands/code/links/IDs/errors exact). This conversation only: `stillmark caveman on|off|lite|full|ultra --json` (after `off`, drop the rules even if saved on). Saved: add `--save` or `stillmark config set --caveman=<level> --json`. Context files only (never ROADMAP, COVERAGE, plans, CHANGELOG): `stillmark caveman compress <file>`, rewrite per `instructions`, `stillmark caveman verify <file>` until clean, or `stillmark caveman restore <file>`. `stillmark caveman --json` shows rule cost and savings.

**README generator and refactorer:** never write a README from memory. `stillmark readme plan [--file=<path>/README.md] --json` returns the real project facts (`facts.runCommands`, workspaces, bin, env var names, linkable files), the template `outline`, `factsToKeep`, and `instructions`, and backs up the current README. When `needsClarification` is true, ask which of the returned `templates` to use, then `readme plan --template=<id>`. Write with only those facts; then `stillmark readme check --json` until `issues` is empty, or `stillmark readme restore --json`.

**Notifications:** channels per user in `~/.stillmark/notify.json`, never in the repo (`stillmark notify add telegram --token=<t>` after messaging the bot once, `notify add discord|slack|webhook --url=<webhook>`, or `notify add desktop` for a native notification on this computer). Every finish, automatically: `stillmark notify hook install --agent=codex --json` adds a top-level `notify` to `~/.codex/config.toml`; when `ok` is false because another program already owns it, tell the user and leave it. Only when `stillmark notify --json` shows `hooks.codex` false and channels on, end every run with `stillmark notify send "<one-line outcome>" --status=done|failed|waiting --json`.

**CHANGELOG.md:** public, plain language for users, never file names or secrets. `stillmark changelog --json` previews; `changelog sync` creates or updates it from tags (or package.json version bumps), done roadmap items, and `feat`/`fix` commits, never rewriting released sections; `roadmap done` lists the item under Unreleased when the file exists; `changelog add "<text>" [--group=fixed]` for anything else; reword unclear Unreleased entries, then `changelog check --json` until clean.

**Clickable links (mandatory):** every reply that creates, changes, shows, or mentions a plan, findings, progress, roadmap, or coverage file must include a clickable markdown link to it. Paste the JSON `link` field verbatim, or build `[TASK_PLAN.md](<absolute path, forward slashes>)` from `location`. Never only a path in backticks.

**Auto-update:** start each `/stillmark` with `stillmark update --json` (npm is checked at most once per `update.intervalHours`, default 24h). When `updateAvailable` is true, run `recommended`, tell the user in one line, then continue. Ignore `error`.

**First run:** when `stillmark config status --json` reports `needsFirstRunPrompt`, ask whether to version design learnings and what to generate now (numbered multiple choice: All, `DESIGN.md`, `PRODUCT.md`, `COVERAGE.md`, roadmap history from `git log`, roadmap items from code `TODO`/`FIXME` comments via `stillmark roadmap todos --add --json`, code style learnings, Nothing). Record with `stillmark config set --design-system=true|false --prompted --json`, generate the picks, then ask whether to commit only those files, showing the list and the exact `proposedMessage` from `stillmark git setup-files --json` (yes = `stillmark git setup-commit [--message "<msg>"] --json`). Never add scopes or markers from your own rules (like `(t)`) to Stillmark commit messages without asking.

**Global install:** if this repo has no `stillmark.config.json` / `ROADMAP.md`, ask once before running `stillmark init --json` (planning files only). This prompt being loaded means Stillmark is installed: never run `stillmark install` or copy prompt files into the repo unless the user explicitly asks.

**Agent entry:** `/stillmark <args>` mirrors `stillmark <args> --json`. Do not use `/coverage`; use `/stillmark coverage …` for COVERAGE.md (help, update workflow, or free text). Playbook: stillmark skill `reference/coverage.md`.

For UI work, use `/stillmark design` or `/stillmark` with browser selection and free-text feedback; follow the stillmark skill `reference/` playbooks.
