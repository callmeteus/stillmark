Como funciona

Você descreve o que precisa mudar no chat. O Stillmark organiza estratégia, trabalho do momento e testes em três blocos claros.

  • Roadmap

    Compartilhado com o time

    Metas e prioridades de longo prazo que todo mundo vê no repositório.

  • Plano atual

    Privado na sua máquina

    Tarefas concretas do que você está entregando agora, sem publicar plano pela metade.

  • Checklist de testes

    Compartilhado com o time

    Lista simples do que já está coberto por testes, para não esquecer o que importa.

Companheiro de cobertura de testes

O COVERAGE.md é um checklist só com caixas, agrupado por área. Sem porcentagens nem blocos de texto - apenas casos marcados como happy, sad, edge ou security que registram o que de fato está testado.

Via /stillmark coverage

/stillmark coverage mostra ajuda, /stillmark coverage update reconcilia com mudanças no git e texto livre após /stillmark coverage edita o checklist em linguagem natural.

Formato rígido

O stillmark coverage validate detecta texto legado, tags erradas e títulos vazios antes do commit.

Updates com git

O stillmark coverage update lista arquivos de código e de teste alterados desde o último commit do COVERAGE.md para o agente saber o que reconciliar.

Companheiro de design de UI

Aponte o que está errado no app em execução e diga o que mudar. O Stillmark liga esse feedback ao seu projeto em vez de remendos soltos.

Seleção no browser

Selecione um elemento no preview local. O agente encontra a tela ou o componente correspondente no código.

Via /stillmark design

Peça ajustes de espaçamento, tipografia, cor ou layout em linguagem natural, ou comece com /stillmark design e um brief curto.

Polimento consistente

Playbooks de design vêm na skill stillmark para o visual ficar alinhado entre sessões.

Companheiro de planejamento

Transforme intenção vaga em roadmap compartilhado e lista de tarefas privada, sem editar markdown a cada mudança.

Linguagem natural

/stillmark cuida de adições, adiamentos, prioridades e movimentações. O CLI preserva seções, IDs e histórico.

Escopo e privacidade

Conteúdo sensível no roadmap e trabalho fora do objetivo atual são sinalizados antes de ir para arquivos compartilhados.

Trabalho longo

Quando uma tarefa atravessa várias rodadas do agente, atualizações aprovadas do plano são salvas para a execução continuar com segurança.

Preferências do workspace

O Stillmark mantém planos de tarefa na sua máquina por padrão e pergunta uma vez quanto do .stillmark você quer versionar no git.

Planos privados

Planos de execução ativos ficam locais. Só o roadmap e o checklist de testes são pensados para o repositório do time.

stillmark config

No primeiro uso, stillmark config status pergunta se arquivos de referência de design em .stillmark entram no controle de versão do projeto.

Git opcional no roadmap

Se você habilitar na config, o Stillmark pode commitar ou enviar o ROADMAP.md - nunca a pasta privada de planos.

Recursos

Linguagem natural e comandos

Adicione, adie, repriorize e mova itens sem editar markdown manualmente.

Escritas incrementais seguras

Os parsers preservam seções, IDs e histórico não relacionados.

Guardas de escopo e privacidade

Trabalho fora do escopo e conteúdo sensível no roadmap são bloqueados por padrão.

Modo long-running

Mudanças autorizadas no plano são salvas antes de o agente continuar.

Aprende com você

Mensagens de commit seguem o seu git log recente, sem template fixo de roadmap. Pré-visualize com stillmark git commit-style.

Git opcional no roadmap

Commit ou push só do ROADMAP.md quando você habilitar na configuração.
